# 小红书 mns x3 签名 — JSVMP + 自定义 XTEA + F6 置换

> 复现对象：`经典 不开源/小红书-mns签名-2026-08-31` · 技术分类：`vm` `encrypt` · 状态：✅ 可复现（离线 4/4；VM 10/10；线上 200，2026-08-31）

## 站点与目标

- 站点：`https://www.xiaohongshu.com/`（mnsv2 JSVMP，2026-08 版）
- 加密参数：请求头 `X-S` 中的 `x3` 字段（`mns0201_` + 128 字符）
- 目标接口：`/api/sns/web/v1/homefeed` 等；`c = uri + body`，`u = md5(c)`，`p = md5(uri)`

## 技术要点

- 保护类型：288KB VM 源码运行时 `eval`（233K 字符字节码 + 81 操作码解释器）
- 算法：89B 明文 → LE 打包（24 词 + 长度词）→ XTEA（8 轮，delta `1013904243`）→ 96B 密文
- 编码：标准 base64 的 6bit 分组 → 静态置换 `F6` → 64 字符自定义字母表
- 明文结构：版本头 `[121,104,96,41]` + rnd + 毫秒时间戳 + counter + c 长度 + u/p 反码 XOR g + 常量块

## 逆向摘要

- 入口定位：`X-S` 请求头断点回溯；VM 源码在运行时 `eval`，改一行让 eval 内容落盘后提取
- 还原过程：
  1. 先抓 192 轮 XTEA 轮函数参数，确认轮函数、密钥、delta、轮数
  2. 黑盒探测编码器：受控输入穷举 6bit 值 → 得到静态置换 `F6`（比反汇编快一个数量级）
  3. 明文 89B 逐字段对齐：打包用 LE uint32，末尾追加原始长度词
  4. `g = ((~rnd) & 0xFF) * 0x01010101`，u/p 字段 = 大端反码 XOR g
- JS→Python 差异：`>>`/`<<` 全按 ToInt32；`(a>>5 ^ x<<2)` 的加法优先级（JS `+` 高于 `^`）

## 备注

- 失效风险：VM 版本/操作码表随站点更新；F6 与字母表需重新探测
- 坑：确定性补环境（`Math.random=0.5`）会让 XOR 掩码 g 恰为 0，u/p 看似纯反码；必须用真随机环境做差分
- 服务端三态：406=签名拒 / 461=风控 / 404=端点；风控期一切被拒，别误判签名
- 样例为已过期抓包（时间戳/counter 固定），仅用于离线算法比对，不能用于真实请求
